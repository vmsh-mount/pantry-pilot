Design Mockup · Nutrition Unification

One nutrition surface, not three

Today the dashboard has three separate nutrition surfaces stacked back to back: the hero's calorie badge, a "Nutrition" card with a gap summary + nav links, and a second, separately-labeled "Nutrition" macro panel right below it. Micronutrients (iron, B12) exist in the data but are never actually shown — just a buried text fragment. This mockup proposes one card that's glanceable by default and expands for full macro + micro detail.

1Before — three surfaces, one screen

Hero badge (calories only) → separate gap-card with its own "Nutrition" header + nav rows → a second "Nutrition" eyebrow + dot-bar panel below it. Protein and fiber numbers effectively appear twice.

4What this fixes
Unifies: one "Nutrition" label, one card, one visual language (dot-bars, same size and style everywhere) instead of a list-card and a separate panel duplicating protein/fiber.
  • Macro rows (Calories, Protein, Fiber, Sodium) are always visible, full-size — same legibility as today's existing panel. Nothing that's currently easy to read gets smaller.
  • Navigation rows (Household targets / This week's report / Fix these in my cart) stay exactly as visible as they are on the current gaps card — never hidden behind a tap.
  • Micronutrients (Iron/B12) get the reveal treatment, not the important stuff — they have no numeric target in the backend today, so they're shown as neutral "watch" chips behind a small toggle rather than crowding the main card with two items that read "no data."
  • One data fetch — worth flagging for the PRD: today the gap-summary text and the dot-bar panel come from two different API calls with different latency (gaps can take 15–20s). Unifying the UI doesn't by itself unify the data source; that's a backend sequencing question the written PRD needs to resolve.
